# 管理后台使用指南

地址：`https://你的域名/admin/`，账号为 `config.yaml` 中的 `admin.username`（默认 `admin`）与 `admin.password`。

> 忘记密码：直接修改 `config.yaml` 里的 `admin.password` 并重启，旧会话会全部失效。

## 概览

- **今日成交额 / 累计成交额**：按订单金额（人民币）统计已支付订单。
- **可用支付渠道**：`可用 / 总数`。有渠道初始化失败时会显示红色徽标，页面顶部也会给出提示，点进去能看到具体原因（通常是密钥格式或参数错误）。
- **商户通知**：待投递数量与已放弃数量。失败的通知可以在订单详情里手动补发。
- **成交趋势**：最近 30 天（移动端默认 7 天）的成交金额。
- **接入信息**：支付地址、API 下单地址、查询 / 退款地址，点右侧按钮一键复制。

## 支付渠道

一个「支付渠道」= 一个易支付 `type` + 一个上游驱动。例如把标识 `alipay` 绑定到支付宝驱动。

新建流程：

1. 点「新建渠道」，选择**渠道驱动**（支付宝 / 微信支付 / PayPal / Stripe / 模拟支付）。
2. **支付方式标识**：商户下单时传入的 `type`，必须与 new-api「充值方式」里的 `type` 一致。只能用小写字母、数字和下划线，**创建后不可修改**（存量订单与上游回调地址都绑定了它）。
3. **显示名称**：展示在收银台页面上，例如「支付宝」。
4. 填写该渠道的参数，各字段含义见 [渠道申请与配置](channels.md)。密钥类字段既可以粘贴内容，也可以填服务器上的文件路径（如 `/app/certs/apiclient_key.pem`）。
5. 如果该渠道需要在上游后台配置回调地址（PayPal、Stripe），页面底部会显示需要填写的**上游回调地址**，复制过去即可。
6. 点「保存并生效」。保存时网关会用这份配置实际初始化一次渠道，密钥不对会直接报错，不会保存成一个用不了的渠道。

其他操作：

- **启用 / 停用**：列表里的开关，立即生效。**停用的渠道不再接受新订单，但仍然会处理存量订单的上游回调**，所以暂停收款时请用停用，不要删除。
- **删除**：该渠道的待支付订单将无法再接收回调（买家如果此时付款，钱到了但订单不会入账），确认框里也有提示。
- **修改密钥**：已保存的敏感字段显示为 `******`，保持不变即沿用原值；要更换就清空后粘贴新值。

## 商户

一个接入方（如一套 new-api）对应一个商户。

- **新建商户**：填个名称即可，商户 ID 留空会自动从 1001 递增，密钥自动生成。创建后会弹出「支付地址 / 商户 ID / 商户密钥」三项，直接复制到 new-api。
- **查看密钥**：列表中密钥是脱敏的，点「查看密钥」可以取出明文。
- **重置密钥**：旧密钥立即失效，商户侧必须同步更新，否则下单和验签都会失败。
- **启用 / 停用**：停用后该商户不能再下单，但已支付订单仍会正常通知。

## 订单

- 支持按平台订单号、商户订单号、上游交易号、商品名模糊搜索，并可按支付方式、支付状态、通知状态筛选。筛选条件会保存在网址里，可以直接把链接发给同事。
- 点击平台订单号进入详情，可以看到金额、上游交易号、付款人、各时间点，以及商户通知的投递次数、下次重试时间和最近一次失败原因。

详情页的两个运维操作：

| 按钮 | 何时用 | 作用 |
| --- | --- | --- |
| **补发通知**（已支付订单） | 商户侧当时宕机或代码有 bug，导致通知失败甚至被放弃 | 重置重试计数并立即重新投递一次通知 |
| **向上游查询**（未支付订单） | 买家说已经付了，但订单还是未支付 | 立刻向支付宝 / 微信 / PayPal / Stripe 查询真实状态，确认已付则入账并通知商户 |

> 正常情况下不需要人工干预：上游回调、买家跳回、收银台轮询三条路径都会确认支付结果，通知失败也会自动重试 12 次（约 25 小时）。

## 常见场景

**换了域名怎么办？** 修改 `server.base_url` 并重启，然后到各渠道后台把回调地址（PayPal / Stripe 的 Webhook）改成新域名。旧域名上还没支付的订单，其回调地址仍是旧的，建议等它们过期。

**怎么先跑通全流程？** 新建一个「模拟支付」渠道，用它下一笔订单，收银台会出现「模拟支付成功」按钮，点一下就能走完回调 → 入账 → 通知商户的完整链路。**验证完请删除该渠道。**

**后台打不开？** 如果显示「管理后台前端尚未构建」，说明编译时没有构建前端，执行 `make build` 重新编译即可；若提示未启用，检查 `config.yaml` 里是否设置了 `admin.password`。
