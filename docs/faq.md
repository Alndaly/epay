# 常见问题排查

排查顺序建议：**网关日志 → 管理后台订单详情 → 上游渠道后台**。

```bash
docker compose logs -f --tail=200      # Docker
journalctl -u epay -f                  # systemd
```

## 下单相关

**提示「签名校验失败」**
参与签名的参数与实际发送的不一致。常见原因：签名后又修改了某个参数；商户密钥填错或重置后商户侧没更新；金额格式不一致（如签名用 `10` 发送 `10.00`）。签名规则见 [接口文档](api.md#签名算法)。

**提示「不支持的支付方式：xxx」**
后台没有这个「支付方式标识」，或该渠道已停用。检查 new-api 充值方式里的 `type` 与后台渠道标识是否完全一致（区分大小写，网关只接受小写）。

**提示「支付渠道下单失败，请稍后重试」**
上游拒绝了下单请求，具体原因在网关日志里，例如：

| 日志片段 | 原因 |
| --- | --- |
| `ACQ.TRADE_BUYER_NOT_MATCH` 等支付宝错误码 | 参数或产品权限问题，按支付宝错误码排查 |
| `应用私钥` / `密钥既不是 PEM 也不是合法的 Base64` | 密钥内容或路径填错 |
| 微信 `SIGN_ERROR` | 商户证书序列号与私钥不匹配 |
| PayPal / Stripe `401` | Client ID / Secret / Secret key 不正确，或沙箱与正式环境混用 |

**后台渠道显示「初始化失败」**
密钥解析失败或必填参数缺失，鼠标悬停徽标或进入编辑页可看到完整原因。修正后保存即可，保存时会先实际初始化验证。

## 支付结果相关

**买家付了钱，订单仍是「待支付」**

1. 后台订单详情点「向上游查询」，直接向渠道确认。如果确认已付，会立即入账并通知商户。
2. 若查询显示未支付，说明钱没到这笔订单上（可能买家付到了别的订单，或支付未完成）。
3. 如果经常需要手动查询，多半是**上游回调收不到**：
   - `server.base_url` 必须是公网可访问的 HTTPS 地址；
   - PayPal / Stripe 需要在其后台配置 Webhook 地址 `{base_url}/notify/paypal`、`{base_url}/notify/stripe`，并订阅正确的事件；
   - 反向代理不要拦截 `/notify/` 路径，也不要对其做 IP 白名单；
   - 查看日志中是否有 `上游通知校验失败`。

**日志出现「实付金额与订单不一致，拒绝入账」**
上游回调的金额与下单时记录的金额或币种不符，网关拒绝入账（这是防篡改保护）。外币渠道改过汇率、而订单是改汇率之前创建的，也会触发。核对无误后可在上游后台原路退款。

**日志出现「上游通知校验失败」**
回调验签没过：微信 / 支付宝多为公钥配置错误；Stripe 多为 Webhook 签名密钥不对；也可能是服务器时间偏差超过 5 分钟（微信、Stripe 都会校验时间戳）。先 `date` 确认服务器时间，必要时开启 NTP。

## 通知商户相关

**商户没收到通知 / 通知状态为「通知失败」**
订单详情里能看到最近一次失败原因：

| 原因 | 处理 |
| --- | --- |
| `connection refused` / 超时 | 商户服务不可达，恢复后点「补发通知」 |
| `商户响应 HTTP 200: "..."` | 商户没有返回 `success`。按协议必须返回纯文本 `success` |
| `商户响应 HTTP 404/500` | 通知地址不对或商户处理逻辑报错 |

网关会自动重试 12 次、跨度约 25 小时，期间商户恢复即可自动成功，不必急于人工干预。

**商户重复到账**
同一笔订单可能收到多次通知（重试、上游重复回调），商户侧必须按 `out_trade_no` 做幂等。new-api 自身已做处理。

## 管理后台相关

**打开 `/admin/` 提示「管理后台前端尚未构建」**
编译时没有构建前端。用 `make build`（需要 pnpm）或 Docker 构建即可，Docker 镜像内已包含前端。

**访问 `/admin/` 返回 404**
`config.yaml` 里没有设置 `admin.password`，后台未启用。启动日志会有「未设置 admin.password，管理后台未启用」。

**提示「登录失败次数过多」**
同一 IP 15 分钟内失败 10 次会被锁定，等待 15 分钟，或重启服务清空计数。

**登录后立刻掉线**
浏览器没有保存 Cookie（会话 Cookie 限定路径 `/admin`，且 HTTPS 站点下带 `Secure` 标记）。确认使用 HTTPS 访问，且 `base_url` 与实际访问地址一致。

## 运维相关

**能不能多实例部署？**
当前存储是 SQLite（单连接 + WAL），适合单实例。多实例需要按 `store.Store` 接口实现 MySQL / PostgreSQL 版本，见 [开发指南](development.md)。

**订单会自动清理吗？**
不会，订单会一直保留。如需清理可自行对数据库执行删除，建议保留至少一年以便对账。

**汇率怎么维护？**
PayPal / Stripe 渠道使用你在后台填写的固定汇率，网关不会自动更新。汇率波动较大时请定期调整，改动只影响之后创建的订单。
